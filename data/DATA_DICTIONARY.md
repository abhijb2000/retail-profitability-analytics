# Dataset dictionary and provenance

All records are generated by src/generate_data.py (seed 42), using fictional products/customer IDs. No personal data or external dataset was used. 8,000 generated orders contain 16,133 original lines; 60 duplicates yield 16,193 raw rows. Forty original lines have invalid fields; 50 region strings require normalisation. Accepted data contains 7,980 order IDs after validation.

| Field | Type / meaning |
|---|---|
| line_id | unique order-line key; duplicate key uses first-record-wins |
| order_id | purchase identifier; repeats across product lines |
| order_date | ISO purchase date, 2024–2025 |
| customer_id | fictional customer key |
| region | North, South, East, West |
| channel | Online or Store |
| product_id, product | fictional product identifier/name |
| category | Electronics, Fashion, Home, Stationery |
| quantity | positive integer units |
| unit_price, unit_cost | list sale price and unit procurement cost, INR |
| discount_pct | fraction from 0 to 1, not percentage points |
| returned | 1 = entire line returned; 0 = retained |
| gross_sales | quantity × unit_price |
| discount_amount | rounded gross_sales × discount_pct |
| billed_sales | gross_sales − discount_amount |
| refund_amount | billed_sales if returned, otherwise 0 |
| net_sales | billed_sales − refund_amount |
| cogs | quantity × unit_cost if retained, otherwise 0 |
| gross_profit | net_sales − cogs |
| month | YYYY-MM purchase month |
| discount_band | 0%, 5–10%, or 20%+ for this generated dataset |

Raw CSV contains the first 14 fields. Derived financial fields are calculated by the pipeline. The discount labels match this dataset's discrete generated discounts; change the band logic if ingesting arbitrary discounts. Each line may be independently returned, so an order can include retained and returned lines. Probability of returns is higher for Fashion and heavily discounted lines by design. Promotional seasonality is explicitly designed by the generator.

CSV files use UTF-8, comma separators, dot decimal separator. The rejected file retains raw source values, source row number and validation reason. SQLite financial fields use REAL; line monetary calculations use decimal half-up rounding before insertion. For production accounting, use decimal database types or integer minor units.
